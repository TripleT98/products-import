# Формат импорта XLSX

Правила чтения XLSX, сопоставления колонок, валидации строк и обработки изображений. См. также [чтение книги](workbook-reader.md) и [валидацию строк](row-validation.md).

## Сопоставление

Сопоставлять по нормализованному заголовку, а не букве колонки. Удалять BOM и крайние пробелы. Регистр заголовков сохраняется; одинаковые нормализованные заголовки неоднозначны и отклоняются. Положение колонок в книге произвольное.

| Заголовок | DTO / JSON | Требование |
|---|---|---|
| Внешний код | externalCode | Обязательная колонка и непустое значение |
| Наименование | name | Обязательная колонка и непустое значение |
| Описание | description | Необязательно, отсутствие/пустота → пустая строка |
| Цена: Цена продажи | price | Обязательная колонка; > 0 |
| Закупочная цена | purchasePrice | Обязательная колонка; >= 0 |
| Доп. поле: Ссылка на упаковку | attributes + imageCandidates | Необязательная колонка |
| Доп. поле: Ссылки на фото | attributes + imageCandidates | Необязательная колонка |
| Доп. поле… | attributes | Динамические ключи, без изменения кода |

UUID, «Код», «Минимальная цена» не заменяют указанные поля. Стандартные колонки, отсутствующие в сопоставлении, игнорируются. «Все основные поля» карточки — поля products, включая выбранные purchasePrice/timestamps; остальные колонки не добавляются в модель автоматически.

## Структура и ограничения книги

Один непустой лист; листы без непустых значений игнорируются. Несколько непустых листов или отсутствие непустого листа — фатальная ошибка книги. Заголовки всегда в строке 1. Обязательная колонка отсутствует, повторяется заголовок или нормализованный ключ доп. поля пуст/повторен — фатальная ошибка структуры; данные не импортировать. Полностью пустые строки пропускать; реальные номера Excel сохранять в issues. Ячейка с формулой считается непустой.

Формулы в импортируемых полях, включая доп. поля и источники URL, не вычислять: ошибка строки `FORMULA_NOT_ALLOWED`, cached result не использовать. Формулы в игнорируемых колонках не исполнять и не импортировать. Внешние книги/изображения не разрешать и не загружать. Гиперссылки в OOXML допустимы как неисполняемые метаданные, без открытия ресурсов. Макросы/зашифрованные книги не поддерживаются.

Конкретизация настраиваемых начальных лимитов: файл 10 MiB; сумма распакованных частей ZIP 100 MiB; не более 1000 ZIP-частей; коэффициент распаковки не более 100; не более 10000 непустых строк данных и физический номер строки не выше 100001. Лимиты применяются при безопасном чтении, без полной распаковки на диск; дублирующиеся имена ZIP, traversal/опасные пути, DTD/внешние сущности отклоняются. API проверяет транспорт/OOXML-контейнер до очереди, worker проверяет листы/заголовки/строки до записи. Общая политика ограничений одна для API и worker; параметры задаются через переменные окружения.

## Строки и десятичные значения

- Trim externalCode и name, оба обязательны. Код — строка, ведущие нули текстовой ячейки сохраняются. Для целочисленной числовой ячейки кода сохранять ведущие нули, явно заданные простым форматом вида `000000`; при общем формате — обычная целочисленная запись без экспоненты. Сложный неоднозначный формат идентификатора отклонять понятной ошибкой строки; не угадывать отсутствующие нули и не вычислять формулы. Булевы/ошибочные ячейки в основных полях отклонять.
- description — текст или пустая строка, безопасный текстовый вывод. Ограничение длины имени/кода не вводится молча: при схеме учитывать индекс PostgreSQL и проверять допустимые размеры перед записью.
- Числовые ячейки читать без промежуточного float, использовать сохранённое значение OOXML/точное десятичное представление. Текст: `1320,00`, `1320.00`, `1 320,00`, NBSP/узкий NBSP как разделитель групп. Группы тысяч — по три цифры; знак минус только в начале. Не принимать смешанные точку/запятую, валютные символы, текстовую экспоненту или неоднозначное `1,320` как тысячи. Значения с более чем двумя дробными знаками допускаются как точные десятичные входные данные и округляются HALF_UP до 2 знаков для хранения. Отрицательная цена/закупка недопустима; цена после округления должна оставаться > 0. Пустое/невалидное число не заменять нулём.
- Расчёт discount = `(sale - purchase) / sale * 100` по точным исходным десятичным значениям, затем HALF_UP до двух знаков; округлять только результат формулы, не промежуточное деление. Сохранять price/purchasePrice с HALF_UP до двух знаков. Это уточнение не влияет на образец; граничные дробные случаи отдельно тестируются валидация строк. Отрицательный discount допустим. Нулевую цену и значения вне DECIMAL(18,2), включая discount, отклонять как ошибку строки. Максимальный модуль хранимого значения `9999999999999999.99`; не использовать IEEE float в расчётах.
- JSON price/purchasePrice/discount — канонические строки с точкой и ровно двумя дробными знаками, без `+`, экспоненты и отрицательного нуля.
- Повтор externalCode в файле: первая валидная DTO-строка резервирует код; следующие дают `DUPLICATE_EXTERNAL_CODE`. Ошибка записи этой первой строки не даёт последующей строке переопределить правило. Невалидная до создания DTO строка код не резервирует.

## Атрибуты и изображения

Внутренний RowDTO: rowNumber (integer >=2), externalCode/name/description (string), sale/purchase как точные decimal-входы, price/purchasePrice/discount как канонические decimal strings, attributes (упорядоченные пары key/value), imageCandidates (URL в порядке). Не переносить этот DTO напрямую в публичный API; Entity не сериализовать.

Источники URL: сначала упаковка AK, затем фото AL, разделитель запятая, trim, удаление дублей внутри товара с сохранением первого порядка. Заголовки находить по именам даже после перестановки колонок. Исходную строку ссылочного поля также хранить как атрибут. URL не исправлять догадками; разрешены только HTTP/HTTPS. Пустой источник не создаёт изображений. Ошибка URL/загрузки даёт warning, товар сохраняется. Успешные записи содержат исходный url и публичный локальный path `/images/...`, position с 0. Отсутствующий URL удалить при upsert; прежнюю рабочую копию того же URL сохранить при повторном сбое; без копии не создавать фиктивную запись. Один файл может использоваться несколькими товарами; удалять только при отсутствии ссылок.

Загрузчик проверяет реальные адреса и каждый redirect: запрет loopback/private/link-local/служебных IPv4/IPv6, DNS rebinding через закрепление проверенного IP для соединения, только HTTP(S), не передавать JWT. Начальные конфигурируемые лимиты: connect 3s, общий запрос 10s, 3 redirects, 5 MiB на изображение. Проверять реальное изображение (JPEG/PNG/WebP/GIF), безопасное имя, файл вне исполняемого каталога. Локальный HTTP test server разрешать только явной тестовой конфигурацией. Скачивать до транзакции; rollback удаляет новые бесхозные файлы, после commit убирать устаревшие, сохраняя совместно используемые.

## Ошибки и прогресс

Реальные коды ошибок строк включают `MISSING_REQUIRED_VALUE`, `INVALID_PRICE`, `INVALID_PURCHASE_PRICE`, `DECIMAL_OUT_OF_RANGE`, `FORMULA_NOT_ALLOWED`, `DUPLICATE_EXTERNAL_CODE`, `PRODUCT_WRITE_FAILED`. Предварительные `INVALID_WORKBOOK`/`INVALID_HEADERS` из контракт не являются публичными job fatal codes: worker сохраняет `WORKBOOK_INVALID` либо `IMPORT_FAILED`, publisher — `QUEUE_PUBLISH_FAILED`. Image warning codes: `IMAGE_URL_REJECTED`, `IMAGE_ADDRESS_REJECTED`, `IMAGE_DNS_FAILED`, `IMAGE_HTTP_ERROR`, `IMAGE_TIMEOUT`, `IMAGE_TOO_LARGE`, `IMAGE_INVALID_CONTENT`, `IMAGE_REDIRECT_REJECTED`, `IMAGE_DOWNLOAD_FAILED`, `IMAGE_STORAGE_FAILED`. Сообщение безопасное, без stack/raw URL. field — DTO camelCase, `attributes.<key>` или `images`; rowNumber/externalCode/field могут быть null для системной ошибки. [Текущий API](openapi.json), [валидация](row-validation.md).

queued → processing → completed/completed_with_errors/failed. Completed без issues; completed_with_errors при row errors или warnings; failed при фатальной книге/системном сбое. Пустые строки не учитываются. После нормального завершения processedRows = createdProducts + updatedProducts + failedRows; warningCount отдельно. totalRows=null до подсчёта; failed может иметь частичный прогресс. Успешные предыдущие строки не откатывать из-за следующей ошибки. Подробные JSON-схемы: [openapi.json](openapi.json).

## Проверки и хранение

```powershell
python scripts/check-workbook.py --xlsx 'path/to/workbook.xlsx'
python scripts/check-docs.py
```

Первая команда читает книгу через CLI без записи товаров, вторая проверяет OpenAPI и Swagger. Параметр `--sample` включает ожидания конкретного контрольного набора и не подходит для произвольной книги. Проверка строк включается параметром `--validate`.

Код товара и ключ атрибута ограничены 255 символами, исходный URL — 2048 байт UTF-8. Денежные значения должны помещаться в DECIMAL(18,2). См. [схему](schema.md) и [валидацию](row-validation.md).

Повторная загрузка может заменить идентификатор и путь изображения, сохраняя отсутствие дублей связей. При предупреждении того же URL сохраняется прежняя рабочая копия. Ранее сохранённые строки не откатываются при поздней фатальной ошибке книги. Автоматическая очистка старых загрузок и файлов после аварий не реализована. Лимиты описаны в [переменных окружения](environment.md).
