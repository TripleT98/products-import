# Приёмочная проверка

Приёмка проверяет запуск приложения и полный сценарий импорта. Используйте отдельное тестовое окружение: рабочая БД и пользовательские загрузки не должны участвовать в проверках.

## Сценарии

- Сборка образов, запуск сервисов, миграции и проверка схемы на пустой БД.
- Явная загрузка fixtures и повторная загрузка без дублирования.
- Вход, защита маршрутов, обработка неверного пароля и истёкшей авторизации.
- Загрузка XLSX при остановленном worker: задача остаётся в очереди, товары ещё не создаются.
- Запуск worker: обработка через RabbitMQ, сохранение прогресса, ошибок строк и предупреждений изображений.
- Просмотр списка, серверных страниц и фильтров; карточка с атрибутами и локальными изображениями.
- Повторный импорт и обновление: стабильные идентификаторы, отсутствие дублей, актуализация атрибутов и изображений.
- Повторная доставка сообщения и перезапуск worker без двойного учёта строк.
- Ошибки книги, строк и загрузки изображений с безопасными сообщениями.
- Swagger UI, соответствие ответов OpenAPI и проверка владельца задачи.

## Команды

Из корня репозитория, при работающем Docker с Linux containers:

```powershell
python scripts/verify.py check
python scripts/check-docs.py
python scripts/check-e2e.py
python scripts/check-workflow.py
python scripts/check-docker-build.py
```

Ожидается код завершения 0. Подробные сценарии и требования окружения: [тестирование](testing.md), [e2e](e2e-testing.md), [CI](ci.md).

Для дополнительной проверки на собственной книге существует `scripts/check-acceptance.py --xlsx <path>`. Этот runner содержит проверки конкретного контрольного набора и не является универсальным валидатором произвольной книги. Исходные пользовательские файлы, их содержимое, контрольные суммы и индивидуальные отчёты в публичную документацию не включаются. Используйте синтетические книги из тестов для воспроизводимого общего сценария.

## Интерпретация результатов

Успешный локальный прогон не подтверждает запуск GitHub Actions: результат CI проверяется отдельно в Actions. Скачивание внешних изображений зависит от сети и источника; предупреждение изображения не равнозначно ошибке строки. Число сохранённых предупреждений не обязательно равно числу неудачных URL, поскольку одинаковые записи могут дедуплицироваться.

Проверки не доказывают устойчивость к произвольной нагрузке, потере volumes или неограниченному отказу инфраструктуры. Ограничения приложения описаны в [README](../README.md) и [архитектуре](architecture.md).
